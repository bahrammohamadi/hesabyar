# 0043 — Invoice output / print / send after sale creation

## گام صفر — رفتار قبلی

### `app/(app)/sales/page.tsx` / `PosModal`
بعد از ثبت موفق فروش، `create_sale` صدا زده می‌شد و `done` با id فاکتور مقدار می‌گرفت. سپس Modal موفقیت نمایش داده می‌شد با:

- لینک `مشاهده و چاپ فاکتور` به `/sales/[id]`
- دکمه `بستن`

یعنی کاربر برای چاپ کامل باید وارد صفحه قدیمی فاکتور می‌شد.

### `app/(app)/dashboard/page.tsx` / `QuickSaleModal`
رفتار مشابه داشت:

- بعد از `create_sale`، صفحه موفقیت داخل Modal نشان داده می‌شد.
- لینک به `/sales/[id]` وجود داشت.
- فقط دکمه بستن داشت.

## صفحه چاپ موجود
فایل:

```text
app/(app)/sales/[id]/page.tsx
```

دکمه چاپ/PDF موجود:

```tsx
<button onClick={() => window.print()} className="btn-primary">
  چاپ / PDF
</button>
```

پس مسیر چاپ کامل همین صفحه legacy است و در این مرحله reuse شد.

## بررسی ارسال پیام/ایمیل/واتس‌اپ
جستجو انجام شد برای:

```text
sms, whatsapp, kavenegar, melipayamak, پیامک, واتس
```

نتیجه:

- لینک‌های ساده `sms:` و WhatsApp در CRM/action menu وجود دارد.
- هیچ integration واقعی با سرویس خارجی مثل Kavenegar/Melipayamak پیدا نشد.
- بنابراین ارسال مستقیم فاکتور هنوز نیازمند انتخاب و اتصال سرویس پیامک/ایمیل/واتس‌اپ است.

## تغییرات انجام‌شده

در هر دو Modal فروش (`PosModal` و `QuickSaleModal`) بعد از ثبت موفق، صفحه موفقیت اکنون این دکمه‌ها را دارد:

1. `مشاهده و چاپ فاکتور` → لینک به `/sales/[id]` و استفاده از چاپ موجود.
2. `ارسال برای مشتری` → فعلاً غیرفعال با tooltip: «به‌زودی - نیاز به اتصال سرویس پیامک».
3. `فاکتور جدید` → فرم را reset می‌کند و همان Modal را برای فروش بعدی آماده می‌کند.
4. `بستن` → Modal را می‌بندد.

## تغییر نکرد

- RPC `create_sale` تغییر نکرد.
- هیچ سرویس ارسال خارجی اضافه نشد.
- چاپ واقعی همچنان از صفحه `/sales/[id]` و `window.print()` انجام می‌شود.
