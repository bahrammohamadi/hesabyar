## ۰) خلاصه در یک خط

**v2 سند درست است و باید مرجع باشد** — اما فقط **متن نثرش**؛ بلوک YAML هر دو فایل باید نادیده گرفته شود. خوشبختانه کاری که تا امروز انجام دادیم دقیقاً همین بوده.

---

## ۱) یافته اصلی: تناقض درونی در خود v2

فایل v2 با خودش نمی‌خواند. بلوک YAML و متن نثر دو چیز متفاوت می‌گویند:

| | YAML frontmatter | متن نثر | توکن واقعی پروژه |
|---|---|---|---|
| `primary` | `#004c3e` → `hsl(169 100% 15%)` | «HSL 165 65% 24%» | `165 65% 24%` ✅ |
| `background` | `#f7faf7` → `hsl(120 23% 97%)` | «HSL 220 26% 97%» | `220 26% 97%` ✅ |

**متن نثر v2 عیناً توکن‌های واقعی پروژه را نقل می‌کند.** یعنی نویسنده‌ی نثر به کد نگاه کرده، ولی YAML از یک generator رنگ (احتمالاً Material Theme Builder) آمده که هیچ ربطی به پروژه ندارد.

📌 **نتیجه:** قانون «hex خام را نادیده بگیر» که در تسک‌ها تکرار می‌شد، نه‌تنها برای v1 بلکه **برای YAML خودِ v2 هم لازم است**. نام فایل v1 (`ignore_colors`) این را می‌رساند، ولی برای v2 چنین هشداری وجود ندارد و می‌توانست گمراه‌کننده باشد.

## ۲) مقایسه دو سند

| معیار | v1 | v2 | برنده |
|---|---|---|---|
| `primary` | `#003631` (سبز تیره‌تر) | `#004c3e` | v2 (نزدیک‌تر) |
| `secondary` | `#712ae2` بنفش پررنگ | `#515f74` طوسی-آبی | **v2** |
| `tertiary` | `#003442` فیروزه‌ای | `#6a3125` قهوه‌ای | — |
| فونت اعداد | **Work Sans** (فونت دوم) | فقط Vazirmatn | **v2** |
| عرض سایدبار | ۲۶۰px | ۲۸۰px | — (هیچ‌کدام؛ ↓) |
| شعاع استاندارد | ۸px | **۱۲px** | **v2** |
| ارتفاع دکمه | ذکر نشده | **۴۴px** | **v2** |

**v1 دو ادعای مشکل‌ساز دارد:**

1. **بنفش `#712ae2` به‌عنوان secondary** — پروژه `--secondary: 210 40% 96%` دارد که یک طوسی روشن است، نه بنفش. اگر v1 دنبال می‌شد، کل معنای semantic توکن‌ها به‌هم می‌ریخت.
2. **فونت دوم Work Sans برای اعداد** — بررسی کردم: در کل پروژه **هیچ ارجاعی به Work Sans نیست**. `tailwind.config.ts` فقط `Vazirmatn, Tahoma, sans-serif` دارد. اضافه‌کردنش یعنی یک وب‌فونت لاتین جدید + ریسک ناسازگاری با ارقام فارسی.

## ۳) انطباق v2 با کد فعلی

آنچه با کد راستی‌آزمایی کردم:

| ادعای v2 | وضعیت پروژه | نتیجه |
|---|---|---|
| `primary` = HSL 165 65% 24% | `--primary: 165 65% 24%` | ✅ دقیق |
| `background` = HSL 220 26% 97% | `--background: 220 26% 97%` | ✅ دقیق |
| RTL کامل | `<html dir="rtl">` | ✅ |
| سایدبار سمت راست | `fixed top-0 right-0` | ✅ |
| کارت سفید + سایه محو | `bg-card` + `shadow-sm` | ✅ |
| ارتفاع دکمه اصلی ۴۴px | `min-h-11` (=۴۴px) | ✅ دقیق |
| توکن‌های finance profit/loss/debt/credit | هر چهار مورد موجود | ✅ |
| `--radius: 0.75rem` (۱۲px) | موجود در globals.css | ✅ |

**اما دو انحراف واقعی پیدا شد:**

### الف) عرض سایدبار
- v1 می‌گوید ۲۶۰px، v2 می‌گوید ۲۸۰px
- کد: `w-64` = **۲۵۶px**

اختلاف جزئی است ولی هیچ‌کدام از دو سند با کد نمی‌خواند. اگر بخواهیم دقیقاً v2 را رعایت کنیم باید `w-64` → `w-[280px]` شود.

### ب) شعاع گوشه‌ها
v2 می‌گوید «۱۲px استاندارد، ۱۶px برای کارت‌ها، از ترکیب گوشه‌های تیز و گرد پرهیز کن». اما در `src/shared/ui/` این توزیع را دارم:

```
rounded-2xl (16px)  → ۱۴ مورد
rounded-full        →  ۶ مورد
rounded-xl  (12px)  →  ۵ مورد
rounded-[24px]      →  ۲ مورد
rounded-3xl (24px)  →  ۱ مورد
rounded-[20px]      →  ۱ مورد
rounded-lg  (8px)   →  ۱ مورد
```

یعنی **شش مقدار مختلف** در کار است، از ۸ تا ۲۴ پیکسل. `--radius: 0.75rem` تعریف شده ولی عملاً استفاده نمی‌شود. این تنها ناهماهنگی سیستماتیک واقعی است.

> شفاف بگویم: بخشی از `rounded-[1.75rem]`ها را خودم در بازطراحی‌های اخیر اضافه کردم، چون مراجع Stitch گوشه‌های بزرگ‌تری داشتند. اگر v2 مرجع نهایی است، این‌ها باید یکدست شوند.

## ۵) توصیه

1. **v2 را به‌عنوان مرجع نثر تثبیت کنید، v1 را بایگانی کنید.** پیشنهاد می‌کنم v1 اصلاً در `design-reference/` نماند تا کسی اشتباهی دنبالش نرود.

2. **در بالای v2 یک هشدار اضافه شود** که بلوک YAML معتبر نیست و منبع حقیقت `app/globals.css` است. الان فقط v1 در نامش هشدار دارد.

3. **یکدست‌سازی شعاع‌ها** — تنها بدهی واقعی طراحی. پیشنهاد: `rounded-xl` (۱۲px) برای دکمه/ورودی و `rounded-2xl` (۱۶px) برای کارت، و حذف `[20px]`/`[24px]`/`3xl`. این یک تغییر بصری است، پس نیاز به تأیید شما دارد.

4. **عرض سایدبار** — تصمیم بگیرید ۲۵۶ (فعلی) یا ۲۸۰ (طبق v2).

5. **Work Sans را اضافه نکنید.** ارقام فارسی با Vazirmatn رندر می‌شوند و `tabular-nums` مشکل هم‌ترازی را حل کرده است.
